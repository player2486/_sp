# 銀行存提款模擬程式說明

## 問題描述

模擬一個銀行帳戶，由兩個執行緒同時操作：
- **存款執行緒**：執行 100,000 次存款（每次 1 元）
- **提款執行緒**：執行 100,000 次提款（每次 1 元）

初始餘額為 1000 元，使用 Mutex 保護餘額，確保最終金額正確。

## 實作方式

### 帳戶結構

```c
typedef struct {
    int balance;
    pthread_mutex_t mutex;
    int deposit_count;
    int withdraw_count;
    int insufficient_count;
} Account;
```

- `balance`：目前帳戶餘額
- `mutex`：保護餘額的互斥鎖
- `deposit_count`、`withdraw_count`：成功交易次數
- `insufficient_count`：因餘額不足而失敗的次數

### 存款執行緒

每次存款時鎖定 mutex，增加餘額後解鎖，確保 `balance += amount` 是原子操作。

### 提款執行緒

每次提款時鎖定 mutex，檢查餘額是否足夠：
- **足夠**：扣除金額，記錄成功次數
- **不足**：記錄失敗次數

### 同步機制

使用 `pthread_mutex_lock()` / `pthread_mutex_unlock()` 保護所有對 `balance` 的存取。

## 執行結果

```
銀行存提款模擬
========================================
初始餘額:          1000 元
存款次數:          100000 次 (每次 1 元)
提款次數:          100000 次 (每次 1 元)
========================================

========================================
執行結果
========================================
實際餘額:          1000 元       ← 與初始餘額相同
預期餘額:          1000 元       ← 1000 + 100000 - 100000
存款成功次數:      100000 次
提款成功次數:      100000 次
餘額不足次數:      0 次

✓ 餘額正確！Mutex 有效防止了競爭條件。
```

## 如果沒有 Mutex？

若移除 `pthread_mutex_lock` / `pthread_mutex_unlock`，`balance++` 和 `balance--` 非原子操作，會發生競爭條件，導致最終餘額不正確。
